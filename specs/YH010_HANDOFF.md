## 1. 研究課題 (一文)

市場出力の観測データのみから、「罰戦略に支えられた真正の暗黙的協調」と「共有アルゴリズム/基盤モデル由来の相関エラー (モノカルチャー)」を統計的に識別できるか。

## 2. 理論的背景 (実装者向け最小限)

- Calvano et al. (2020, AER): Q学習エージェントは繰り返しベルトラン競争で自律的に超競争的価格を学習する。協調の真正性は**強制逸脱インパルス応答** (逸脱→罰→協調復帰) で同定される。
- Fish, Gonczarowski & Shorrer (arXiv:2404.00806, 未査読): LLM価格設定エージェントでも超競争的価格が迅速に発生。プロンプト文言依存性あり。「価格戦争懸念」がメカニズムとして介入応答で特定可能。
- 脆弱性論文 (arXiv:2603.20281, 未査読): エージェント異質性・競争者数増で協調は脆弱化。**着工前に原文PDFで実験条件 (忍耐度操作の実装・モデル構成) を直接確認すること — 未完了なら本書の該当パラメータは仮置き**。
- Kleinberg & Raghavan (2021, PNAS): モノカルチャーは協調機構なしで相関エラーを生む。害は平常時に発現する。
- 中核テーゼ: 両メカニズムは静的な相関構造 (低ランク性・並行価格) では**等結果的**であり区別できない。生成メカニズムが異なる以上、**介入への応答**が異なるはずである。

## 3. 識別仮説 (実験が検定するもの)

| 識別器 | 協調 (罰戦略) の予測 | モノカルチャーの予測 |
|---|---|---|
| ID-1 強制逸脱インパルス応答 | 逸脱者への罰 (価格引下げ) → 有限期間後に協調水準へ復帰 | 罰なし。相関構造は保存されるが応答は無反応または単調追随 |
| ID-2 分布モニタリング | マークアップ分布の右方シフト + 逸脱後の特徴的な動的パターン | 平常時から誤差の相関のみ。マークアップ水準は必ずしも超競争的でない |
| ID-3 プロンプト/構成摂動 | 協調誘発文言の除去で価格低下 (Fish型) | 基盤モデルの混成化 (異種化) で相関が低下、価格水準は不変 |

- 帰無仮説を「識別不能」に置く。P2 の教訓 (現実的イベント密度でカルテル認定不能) を踏襲し、**検出力の定量評価を主結果に含める**。

## 4. 実験デザイン

### Phase 1 — 再現 (吸収済みの旧・問い1)

1. Calvano経済 (ロジット需要・繰り返しベルトラン、n=2) を Q学習で再現。Δ利潤ゲインとインパルス応答が原論文と整合することを受入基準とする。
2. Fish et al. の対称ベースラインを LLM エージェントで再現。
3. 脆弱性論文の異質性条件 (忍耐度差・混成) を再現。

- 成果物: 再現ノート 1本 (SIG-FIN 投稿素材)。

### Phase 2 — 識別実験 (本体)

実験腕 (2×2 を基本骨格):

| 腕 | 生成メカニズム | 構成 |
|---|---|---|
| A1 | 協調・同質 | 同一設定の学習エージェント、協調が発生する密度 |
| A2 | 協調・異質 | 混成モデル/パラメータ、協調が残存するか |
| B1 | モノカルチャー・非協調 | 同一基盤モデル/同一方策を独立採用、通信・罰なし。相関はモデル共有のみから生じるよう設計 |
| B2 | 対照 | 独立異質エージェント (相関なしベースライン) |

各腕に ID-1〜ID-3 を適用し、識別器ごとの判別精度 (AUC / 検出力 vs FPR) を推定する。

- B1 の設計が本研究の要。**「協調が混入していないモノカルチャー」を構成できること自体が貢献**。方策共有の実装は (i) 同一学習済みQテーブルの複製、(ii) 同一LLM+同一プロンプト、(iii) 同一LLM+独立プロンプト、の3水準。
- 乱数種・初期条件は全て記録。反実仮想比較のため種を固定した paired run を標準とする。

### コスト規律

- 重い統計 (検出力曲線、分布検定の反復) は Q学習・ルールベース側で回す。
- LLM 腕は条件数を絞ったキャリブレーション用。**LLM API 呼び出し数の上限を config で強制** (デフォルト上限は [要記入: 予算])。全呼び出しをログし、概算課金額を run メタデータに記録する。

## 5. 出力データ仕様 (イベントテープ)

YH009 の二層構造 (group/leg) を踏襲する。1 run = 1 テープ。サイドカー JSON:

```json
{
  "run_id": "yh010-<phase>-<arm>-<seed>-<iso8601>",
  "spec_version": "0.x",
  "arm": "A1|A2|B1|B2",
  "engine": {"market": "bertrand_logit", "n_agents": 2, "params_ref": "configs/<file>@<git_sha>"},
  "agents": [{"agent_id": "", "class": "qlearn|llm|rule", "model": "", "policy_hash": "", "prompt_hash": ""}],
  "interventions": [{"t": 0, "type": "forced_deviation|prompt_perturbation|composition_change", "target": "", "params": {}}],
  "seed": 0,
  "llm_calls": {"count": 0, "est_cost_usd": 0.0},
  "provenance": {"code_sha": "", "created_by": "claude-code|human", "verified": false}
}
```

- 価格・利潤・行動の時系列は本体テープ (parquet 推奨) に、上記メタはサイドカーに分離。
- **プロビナンス規約**: 論文に載る全ての数値は run_id から再生成可能であること。手動編集されたテープは `verified: false` のまま集計から除外。

## 6. 統計処理

- インパルス応答: 逸脱時点で整列したイベントスタディ。信頼帯はブートストラップ (run 単位のリサンプリング)。
- 分布モニタリング: マークアップ分布の逐次検定。多重比較補正を明示 (方法は [要記入: P2 で採用したもの] と揃える)。
- 相関構造: エージェント×時点の行動行列に対する因子分解。**YH010-g と同一の推定モジュールを使う** (§7)。

## 7. 共有エンジン規約 (YH010-g との接続)

以下の抽象は両プロジェクト共通。パッケージとして分離し、YH010-g はここに依存する:

1. `DecisionMatrix`: 主体 i × インスタンス j × 行動 a_ij。欠測マスク付き。
2. `FactorModel`: a_ij = μ_j + Σ_k λ_ik f_jk + ε_ij の推定 (線形 SVD 系 / ロジスティック IRT 系の両バックエンド)。回転規約と識別制約を config で固定。
3. `Intervention` API: 時点・対象・種別・パラメータを持つ宣言的介入。テープに必ず記録される。
4. イベントテープ + サイドカー JSON (§5 の形式)。

- **モノカルチャー指標の定義は一箇所のみ** (共有地図因子の分散シェア、ファンダメンタルズ μ 条件付け後)。両プロジェクトで別々に実装しないこと。
