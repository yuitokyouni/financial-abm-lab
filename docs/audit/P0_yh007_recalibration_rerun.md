## 2. 付随して確定した事実 — 旧 1-group テスト構成の agg 崩壊

`test_matched_ar1_agg_rate_within_band` の旧構成(全 20 agent が matched_ar1、
margin 3e-5..1e-4 の 1-group)は、修正 φ/σ では **agg_rate = 0.0015** に崩壊する
(目標帯下限は 0.05。seed 42, 400 steps で実測)。

- 原因: φ 上昇(0.418→0.615)で (v−mid) の持続性が増し、innovation σ 減少
  (6e-3→3.81e-3)と合わせて板をクロスする頻度が激減する。全員が persistent な
  1-group では流動性供給側も遅くなり交差がほぼ消える。
- 一方、**実験本体の 2-group dose-match 構成**(7eadfe3 で移行済み: ZI-naive 流動性役
  10 + matched_ar1 戦略役 10、p3d と同一 margin)では戦略群 agg = **0.072±0.01**
  (下表)で帯内に留まり、dose parity は修正値でも成立する。
- 対応: テストを本体と同じ 2-group 構成に更新(1-group 構成は 7eadfe3 以前の
  遺物で、現行実験の代表性が無いため)。旧構成の崩壊はここに事実として記録する。

**不確実性の表記**: 上表・§3 の表の ± は **8 seed 間の標本 SD(ddof=1)**
(`_agg` の実装)。SE ではない。

**対応のある差(seeds 0..7 は両較正で共通、diff = 修正値 − 旧値、SE = SD(diff)/√8)**:

| チャネル | paired diff | SE | t(df=7) | 有意(5%, \|t\|>2.365) |
|---|---|---|---|---|
| zi_matched ret_acf[1] | −0.0402 | 0.0266 | −1.51 | **n.s.** |
| E_W0 ret_acf[1] | −0.0097 | 0.0259 | −0.37 | **n.s.** |
| D1_W0 ret_acf[1] | −0.0196 | 0.0149 | −1.31 | n.s. |
| D2_W0 ret_acf[1] | +0.0163 | 0.0198 | +0.82 | n.s. |
| zi_matched agg | −0.0298 | 0.0005 | **−65.2** | **決定的に有意** |

**判定(事前基準:「zi_matched の対応差が有意であれば項目 1 解消、
そうでなければ未解消」)— 不成立。さらに以下の構造的理由により、項目 1 は
「未解消」ではなく【復元不能】として恒久的にクローズする(追加 seed で
追わない):**

1. 対照 run が確立できるのは「修正値と旧値で ret_acf[1] が分離するか」まで。
   仮に追加 seed で母集団分離を確立しても、元の主張値 −0.094 は n も seed
   構成も不明な**点推定**であり、元記録自身が ±0.06 を持つ。旧値平均 −0.054
   からの距離は約 0.7 SD にすぎず、あの 1 点をどちらの較正に割り当てるかは
   分離が確立しても決まらない。
2. 唯一割り当てを決められたチャネルは agg(t=−65、実質重なりなし)だが、
   **元記録に agg が存在しない**。
3. したがって provenance を解決する経路が存在しない。

- **E_W0 は識別に使えない**(paired t=−0.37)。両較正で区別できない。
- **zi_matched も識別を担えない**。点推定の対応差 −0.040(SE 0.027)は
  t=−1.51 で、n=8 では「動いた」ことすら断定できない。
- ret_acf 系で唯一決定的に φ/σ 感応なのは **agg(t=−65)**だが、
  **元の主張(ecb788d)は agg を記録していない**ため遡及的な識別には使えない。
  教訓: 主張には流動性・約定診断量を添えること(P3 の「流動性診断量を全 run の
  出力に含める」要件を先取りで支持する実例)。
- **状況証拠(統計的識別ではないと明示する)**: パイプラインは決定論的
  (§3.5 の全桁一致確認)なので、「同スクリプト・同 seeds 0..7」という補助仮定の
  下では各較正の出力は一意に定まり、主張値は修正値の決定論的出力と表示桁
  4 数字(2 条件 × mean/SD)すべて一致、旧値の出力とは不一致。ただしこの議論は
  補助仮定(同 seeds)に依存するため、**項目 1 の判定根拠とはしない**。

**この run の主たる収穫は provenance ではなく分散の数字である**:
paired diff の SD は σ_d = 0.0266 × √8 ≈ **0.075**(ret_acf[1]、2,000 step、
legacy 構成)。これにより根拠なしだった必要 seed 数が計算可能になった
(詳細と Week 3 への引き継ぎは `BACKLOG.md`)。同時に、同一 run・同一 seed・
同一介入で **agg t=−65 / ret_acf t=−1.5** という対比は、転写経路
(注文フロー段階 → 価格段階)に沿って測定 S/N が大きく劣化することを示す —
主推定量の設計(ACF を記述統計に降ろし、local projection を主推定量にする)へ
の示唆として BACKLOG に引き継ぐ。

**artifact の自己完結性の欠落(判定根拠の明示)**:
`P0_rerun_yh007_8_p3d.json`(修正値再走)は CLI override 追加**前**に生成されて
おり、args に φ/σ が**含まれない** — 監査対象のパラメータについて JSON は
自己完結でない。この artifact の φ/σ の判定根拠は **(a) ではなく (b)**
(生成時のコード状態 = commit 2534773 + §3.5 の全桁一致による現行コードとの
結合)である。対照 `P0_control_oldvalues_yh007_8_p3d.json` は override 経由の
ため args に phi_ar1=0.418 / sigma_ar1_abs=0.006 を含む(この 2 パラメータに
ついてのみ自己記録)。effective config の全量記録は P1 の導入対象。

**確定が維持される点**:

- **P0 判定不能項目 5(agg parity 参照値 0.102 の由来)は解消のまま**。
  こちらは識別チャネルが agg であり、旧較正 0.1022 vs 修正 0.0724
  (paired diff −0.0298, SE 0.0005)で分離は決定的。docstring の 0.102 は
  旧較正 run 由来と確定してよい。
- 対照の E_W0 = −0.250 が round6 原記録の E(−0.250)と表示桁一致する点は、
  E_W0 チャネル自体が較正を判別しない以上、「round6 原 run は旧値」の
  **追認としては弱い**(P0 §2 の (b) 判定 = git blame が引き続き主根拠)。

**「頑健」の意味の確定**:

- 両較正で保持されるのは**符号構造**(D1_W0 ≈ 0 / E_W0 ≪ 0 の対比)のみ。
  係数の大きさの較正間差は n=8 では確定しない(上表の paired t)。
  S3 主効果(プール)の較正間 contrast も +0.033(対応 SE 0.019、t=+1.7、n.s.)で、
  「両較正で同型」ではなく**「両較正で負・有意、差は検出されなかった」**が
  正しい主張の型。「較正修正に頑健」はこの弱い意味で読むこと。
- **2×2(S2 共有 × S3 sticky)の対応のある差**により、round6 の「必要十分」は
  効果分解の主張へ訂正した。結論は**推定量(層別セル対比かプールか)に依存する**
  ため、推定量・較正込みの表の正は
  **spec 003 §12「訂正・現状整理(2026-08-13)」**(ここには複製しない)。
  要点のみ: S3 主効果はどの推定量・較正でも有意、S2 は層別で n.s.・プールでは
  修正較正のみ有意 = 示唆止まり。
- **§3.8 recenter の採択根拠は符号構造のみに依存**(round6 の二重乖離 =
  D1 に bounce 無し / E に bounce 有り、の対比)→ 採択自体は較正非依存で存続。
- **P3-F の合格は旧キャリブレーション下での条件付き合格**。判定 (i)
  (kronos recenter run の |ret_acf[1]| < 0.1)は φ/σ 非関与だが、判定 (ii) の
  agg parity は旧較正参照値 0.102 に対して行われた。修正値の参照は 0.072 で
  あり、**修正較正下での P3-F 合格は未確認**(→ BACKLOG)。

### 3.5 CLI override 追加の挙動中立性(全 seed・全桁で確認)
