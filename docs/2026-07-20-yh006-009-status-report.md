## 1. YH006 系 (YH006 Phase 1 → YH006_1 Phase 2) — SG の LOB 移植

### 1.1 系譜

研究課題は「**現実的な注文板 (LOB) を介した取引は、Speculation Game の資産駆動型市場機構 (特にファネル構造) をどう変質させるか**」。

```
YH005 (SG aggregate 最小実装 + 3モデル比較)
  → YH005_1 (3層機構の数値実証、round_trips ログ基盤確立)
    → YH006 Phase 1 (SG を PAMS LOB へ移植、2×2 実験、F1 初観察)
      → YH006_1 Phase 2 (100 trial ensemble 化 + ablation、S1〜S6)
        → (将来) YH006_2 (LIMIT 注文拡張 + 論文 Fig.11/12/13 フル再現)
```

議論の展開は「発見 → 統計的検証 → 発見の置き換え → 方法論攻撃への防御 → 因果検証」という連鎖:

1. **F1 初観察 (Phase 1, 単一 seed)**: LOB 化すると初期資産格差 (Pareto) がファネルを大幅減衰させる interaction ≈ −0.27。aggregate では起きない。
2. **S1–S3 (ensemble 化)**: 100 trial で **F1 interaction は null と確定** (CI が 0 跨ぎ、agg 側 CI 幅 0.003 の精度で「真に null」)。単一 seed の −0.27 は LOB の seed 間分散による noise だった。一方、**marginal な世界効果 (LOB ≪ agg のファネル)** は razor-sharp に確定し、副産物として **survival gap** (LOB censoring 81.1% vs agg 0.9%) が本物の発見として浮上。
3. **S4–S5 (A1 ablation: q = 定数固定)**: **仮説 A 単純版 (「q heterogeneity → funnel 汚染」) を反証**。q を切ると uniform LOB (C2_A1) は agg 水準へ戻る (−0.31) が、Pareto LOB (C3_A1) は動かない (−0.09)。ここから **仮説 A revised**(「Pareto LOB では agent が凍結し、初期 wealth 分布が refresh されず persist することが funnel 減衰の dominant 因子」)が浮上。
4. **S5.5–S5.8 (Yuito の方法論的指摘への防御 4 連戦)**:
   - **S5.5**: 「agg と LOB で RT 数が 8 倍違う」指摘 → sub-sample 制御で **H_micro 強支持** (sample disparity では説明不能)。
   - **S5.6**: 「MMFCN 設定の約定 artifact では」指摘 → orderVolume 弾力性 ε(4x)=0.254 で **artifact 説棄却**。
   - **S5.7**: 「censoring 81% vs 0.9% は T 交絡 (1500 vs 50000)」指摘 → raw 比較を retire し、matched KM S(τ) に headline を差し替え。**survival gap は hazard 起源** (agg = ramp→steady ~3e-3/step で cohort 絶滅、LOB = shake-out 後に hazard 凍結)。
   - **S5.8**: 「凍結は有限 T artifact では」→ T=10000 延長で退場 event **0 件** / 5.09M agent-steps、**H_frozen 確定** (h 上限 5.9e-7、閾値の 1/34)。Layer-2-timescale 留保が「測定済み result」に格上げ。

### 1.2 どこで詰まっているか

- **S6 (A3 ablation = lifetime cap τ_max=121 で凍結を人為解除) が実行途中で停止**。dossier (2026-06-07 時点) によれば Windows 側実装は完了 (hook + `LifetimeCapSpeculationAgent` + τ_max 較正 + parity 27 件 PASS) だが、**Mac 側の C3_A3 × 100 trial (~2–3 時間) が未実行**。`data/C3_A3/` も `stage_S6_diff.md` も存在しないことをリポジトリ上で確認済み。これが仮説 A revised の direct causal test であり、Phase 2 の科学的結論 (「凍結 tail を除くと funnel が戻るか」) がここで宙吊りになっている。
- **S5.9 (c_ticks self-consistency = 残存 limitation P2 の解消) が Draft・Yuito 承認待ち**。c_ticks=28 は SG 投入前の揺らぎで較正した値で、投入後 regime に self-consistent でない。gap の「大きさ」には効かない主張だが、trigger 律速か fill 律速かの切り分け (=軸2/YH007 の go/no-go 判断材料) がここに依存。
- **S1-secondary (plan A/B 分岐の bootstrap 最終確定)** も保留 (優先度は Yuito 判断)。

### 1.3 今後の予定

1. **S6 完遂**: Mac で C3 等価チェック → A3 smoke → determinism guard → 100 trial → Windows 集計 + KPI L3 判定。pre-registered 判定: C3_A3 の pooled bin_var_slope が C0u/C2_A1 側 (−0.31〜−0.40) へシフトすれば**仮説 A revised 確定**、C3 のまま (−0.13) なら fail → S7 で別 mechanism 探索。
2. **S5.9 承認 → 実行** (S6 と並走可): SG 投入後 mid で c_ticks を 1 パス再較正 + 少数 seed 再走。funnel gap 維持が主成功条件、trigger 率変化は軸2 go/no-go 診断。
3. **S7 (Phase 2 完了 + proposal 素材)**: S6 完了後に別 plan で。headline 規約 (hazard 構造で張る、raw censoring 比較は retire、全数字に対象物ラベル) は dossier §6 で確定済み。
4. **YH006_2 (将来)**: LIMIT 注文 open 拡張 (zero-fill open ≈30% の解消) + 論文 Fig.11/12/13 のフル再現。

## 3. YH008 — LLM-as-Agent への活性介入 (mech-interp)

### 3.1 系譜

YH001–007 (古典 ABM 再現) とは**別系譜**の方法論的柱。FCLAgent (LLM-as-agent) 系譜に mechanistic interpretability を接続し、Llama-3.1-8B-Instruct の内部表現から**参照点依存的判断 (disposition / ATH 反応) を司る方向 v_ATH を同定し、KO/Rescue で因果検証**する。市場シミュレータは作らず (Stage 5+ に延期)、single-turn 状態アンサンブルで進める。

議論の展開:

1. **設計 v0.3 + 実装ブリーフ + addendum v0.3.2** (正本): 5 固定研究判断 (logit ベース抽出、clean-probe で CoT 汚染回避、単一資産 disposition の再定義など) と Gate 1-3 (KO / Specificity / Rescue) を確定。閾値は事前推測せず Stage 0 で実測して凍結する設計に変更。
2. **GPU セッションでの実行 (2026-05-29、A100)**: v1 → P0 (ATH 構築バグ修正、paired-state 化) → **P0.5 (方向頑健性チェック)**。
3. **P0.5 の結論** (`REPORT_v3.md`): 中立な clean-probe 3 wording すべてで **loss 文脈の ATH 非対称が正** (CI が 0 を除外)。behavioral-framing での符号反転は reason-generation artifact と判定。判定 = **`PASS_STAGE2_LOSS_CONDITIONAL_CONFIRMED`**。disposition proxy は両 framing で正であり、ATH が失敗しても Stage 2 の pivot 先になり得ることも確認。

### 3.2 どこで詰まっているか

- **Stage 2 (loss-conditional v_ATH の同定) が未実行**。`stage2_implementation_brief.md` (次セッションへのタスク指示書) は完成しているが、2026-05-29 の P0.5 以降 outputs に更新がない。
- 実行には **GPU 環境 (A100 実績、RunPod 想定) の再確保と HF gated token の再投入**が必要 — 本リポの CPU 環境では走らない、という構造的な待ち。

### 3.3 今後の予定

1. GPU セッションを立て、Stage 2 ブリーフ + design v0.3 + addendum v0.3.2 を渡して **v_ATH 同定** (canonical wording = `sec1_faithful` 凍結、exploration set のみ使用、held-out は Stage 3 ゲートまで温存)。
2. Stage 2 完了後、**Stage 3: Gate 1-3** (KO で ATH 非対称が減る / specificity が壊れない / Rescue で戻る) を specificity control 込みで判定し、PASS/FAIL を報告して**停止** (Stage 4 以降には進まない、が事前規約)。
3. 方向テンソル / config / ログのアーティファクト保存。

## 4. YH009 — unwind-tape (政策保有株解消イベントスタディ)

### 4.1 系譜

YH シリーズ初の**実証 (実データ) ライン**。YH001–008 の ABM シミュレーションと別系譜で、日本株の政策保有株 (持ち合い) 解消・売却イベントに対する AR/CAR を計測する。思想は「size/ADV・route/support FE で説明できない**残差だけを ABM 候補にする**」— 将来的に YH001–008 系の ABM 研究へ**経験的な錨**を与える接続を意図している。コードはリポルート直下 `unwind-tape/` (新規一次研究ラインのため `imported/` ではない)。

議論・実装の展開 (2026-07):

1. **Task A** (JPX 立会外取引 日次キャプチャ): 実装完了・バックフィル成功・ユーザ Mac に cron 登録済み。鮮度アラーム (営業日 5 日で fail-loud) 実装済み — JPX の掲載保持が 2 週間しかないため、これが唯一の早期警戒網。
2. **Task B** (xlsx→CSV 正規化 + PDF アーカイバ + build round-trip): v0.4 で validator errors=0 warnings=0。URL truncation (C026) と Source_Log ギャップ (C027) を解消。PDF 14/17 アーカイブ (残り 3 件は Reuters paywall 401)。
3. **Task C** (J-Quants V2 + AR/CAR エンジン): V1→V2 移行 (認証・フィールド名短縮) を実機確認して吸収。G004 (Honda) / G008 (Nintendo) の CAR が**独立実装の手計算と 3/3 一致 (diff=0.000000)**。9/12 leg で CAR 計算成功。
4. **系統 B** (shortfall 分解エンジン、MEASUREMENT_SPEC v0.2): 恒等分解 `IS_raw=s1+s2+s3` をテストで固定して実装済み。ただし現データで実値が出るのは G008/L002 の 1 leg のみ。
5. **重要な自己修正**: day 0 規則の穴 — `after_close` 空欄の leg を暗黙に「引け前 (同日)」扱いしていた。日本の売出し開示は大半が引け後のため day 0 が系統的に 1 営業日早くなるリスク → **空欄は計算拒否 (fail-loud) に修正**。

### 4.2 どこで詰まっているか (findings 未確定の理由)

インフラは完成したが、**本分析 (findings) に入る前提が複数未充足**:

1. **day 0 メタデータの穴**: `disclosure_time` / `after_close` が一次資料から未転記。このため **G008/L001 以外の CAR は暫定値**で本分析に使えない。系統 B も同じ理由で G001–G007 が skip され、実値は 1 leg のみ。
2. **サンプルサイズ不足**: N=12 legs (実質さらに少ない)。Baseline_Spec Step 1 すら安定して回せない。**Sampling_Frame.csv の TDnet クエリを実装する母集団拡張 (次タスク "D") が本分析着手の前提**。
3. **業種偏り**: シード 11 groups のうち約 45% が自動車サプライチェーン系 → industry FE と subgroup robustness が必須 (PREREG.md §1/§7)。
4. **PREREG.md が draft・未確定**: 推定窓・モデル選択・day0 規則・20%/100% ADV 境界仮説の草案はあるが、確定日/確定者が空欄。
5. **ユーザ確認待ちの逸脱 1 点**: 系統 B を spec の「調整後終値」でなく**生終値**で実装 (分割銘柄で s3 が壊れるため。Honda 1:3 分割で −ln(3) ずれる)。
6. **運用面**: cron → launchd への切替推奨 (スリープ中の発火を永久に失うため) と、cron 自動発火の初回確認が残っている。

### 4.3 今後の予定 (優先順)

1. **G001–G007 の `disclosure_time` / `after_close` を一次資料 (アーカイブ済み PDF) から転記** → 親 day0 が解決し、CAR 本計算と系統 B の s1/s2/s3 が一気に埋まる。次いで secondary offering 各行の `pricing_date` / `offer_price_JPY` 転記。
2. **Task D: TDnet クエリによる母集団拡張** (Sampling_Frame 実装) — 本分析の前提。
3. **PREREG.md の確定** (ユーザ記入) → Baseline_Spec Step 1 (AR/CAR 本分析) 着手。
4. 系統 B の生終値逸脱の承認、cron→launchd 切替、Reuters 3 件の代替ソース検討。
