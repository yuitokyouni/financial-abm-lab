# リポジトリの配置規約

2026-09-19。配置についてはこの文書を正本とする。各研究の科学的仕様・判定・パラメータは、
引き続きその実験のspecと保存済み来歴に従う。過去の統合specの目標と実装の現状は区別する。

## 所有範囲

```text
experiments/<ID>/   問い、実験固有コード、設定、入力、評価、文書、結果
packages/<name>/    複数の利用側から呼ぶ共通実装
src/fabm/          既存の小さな共通補助コード
tests/            共通API・実装同一性・全体配置のテスト
docs/             全体の使い方、設計判断、横断的な監査・振り返り
imported/         旧リポジトリの履歴・証拠（変更しない）
data/             研究横断のDB・文献データ。実験固有データを新たに置かない
proposals/        採用前の研究提案。検証済み結果とは別
```

`packages/abm_models` は市場モデルの実装であり、それだけでは研究の問いや介入条件は決まらない。
例えばYH001とatlasがCont–Bouchaudを使っても、比較対象・測定・保存する証拠はそれぞれの実験が決める。
一方、YH010-g固有の推奨再構成器をpackageとして配布できることは、共通コードに分類する理由にならない。

## 実験ディレクトリ

必須はREADMEと`experiment.toml`。READMEに問い、使うモデル、実行方法、入力、評価方法、制限を書く。
その他のディレクトリは必要なときだけ作る。`scripts/`と実験直下のPythonモジュールを機械的に統一するために
既存の実行APIを壊してはならない。

実験固有のテストはその実験へ置く。共通実装のparity・APIのテストはrootまたは共通package側へ置く。
依存方向は **実験 → 共通コード**。共通コードから実験へのimportは認めない。
旧コマンドを維持する薄い互換入口は例外として明示し、新規実装を足さない。

## 文書と証拠

全体の説明は`docs/`、個別実験のspec・ノートは`experiments/<ID>/specs/`または`docs/`。
CSV・結果JSON・配列・生ログは文書置場ではなく、実験の`data/`、`runs/`、`reports/`に置く。
`runs/<run_id>/`は原則Git管理外。保存する結果はcommit、seed、設定、入力の識別子を添える。
既存のCSV・JSON・manifest・アーカイブは、配置変更の都合で内容やハッシュを書き換えない。
過去のmanifest内の旧パスは履歴の一部として保持し、移動対応表を参照する。

## 環境とテスト

```sh
uv sync --extra dev
python tools/check_layout.py
uv run pytest -m "not slow"
```

rootの標準テスト範囲は共通コードとYH007/YH009/YH010-g。
YH012はローカルのLOBcoreビルドを必要とするため、既存の専用READMEの手順で別途テストする。
YH008のGPU実行、外部API通信、保存済み39 seedの再実験は配置チェックに含めない。
root workspaceの実験packageは明示列挙する。`experiments/*`を無条件に登録して依存を混在させない。

## 互換性とローカルデータ

`unwind-tape`はYH009の互換シンボリックリンク。Macの定期実行パスを保つために残す。
Git管理外のローカルデータはリモート側では移動できない。更新前に退避し、YH009/YH010-gのREADMEに従って
新ディレクトリへ復元する。Git管理外ファイルを削除する`git clean -fdx`等で対処しない。
